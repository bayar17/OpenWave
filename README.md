# OpenWave rootfs metadata normalization

**Issue:** Rootfs files installed by `DESTDIR`, Meson, CMake and BusyBox can have inconsistent POSIX modes. The original image-building function uses `fakeroot` to set **every** file's ownership to `0:0`, which destroys intended ownership for user private data and the Ocean service account.

## Auditing and correcting rootfs modes (no image)

From the repository root, after installing this script:

```sh
python3 scripts/fix-openwave-rootfs-permissions.py --root rootfs --check
python3 scripts/fix-openwave-rootfs-permissions.py --root rootfs --apply
python3 scripts/fix-openwave-rootfs-permissions.py --root rootfs --check
```

`--apply` only repairs explicitly known directory/configuration modes, home directory modes, and OpenRC service scripts. It refuses unsafe symlinks in protected paths. It reports world-writable regular files and non-sticky world-writable directories instead of silently changing unknown modes. The tool deliberately does **not** normalize executable and shared-library modes indiscriminately, nor does it relabel SELinux files.

## Installation and build integration

```sh
python3 openwave-rootfs-permissions/install.py --dry-run
python3 openwave-rootfs-permissions/install.py
```

The installer validates the `build-openwave` function layout, backs up the original file as `build-openwave.before-permissions.bak`, then adds:

1. `--apply` immediately after the `userspace` stage runs `assemble-openwave-rootfs.py`.
2. An `--image-owners` call **inside the existing fakeroot session after root ownership normalization and before mke2fs**. It reassigns `/Data/Users/<account>` trees according to `/etc/passwd`, `/var/lib/ocean` to UID/GID `1000:1000`, and the D-Bus launch helper to `root:messagebus` mode `4750` if present.

No image is generated by the installer or by the metadata utility. `./build-openwave image ...` remains explicit.

**Important:** `--image-owners` is accepted only inside `fakeroot`, not on a real filesystem. This prevents accidentally chowning host-owned build files. On-disk ownership in the unprivileged build directory remains host-owned; the output image gets the intended ownership via `fakeroot`.

**SELinux:** POSIX modes/ownership are not SELinux labels. The existing OpenWave SELinux policy compilation, file-context paths and boot labeling need to stay active and be tested independently.

**Existing rootfs metadata:** Do not run `chmod -R 755 rootfs`, `chown -R root:root rootfs`, or follow symlinked `/bin` into the host. The utility handles legitimate merged `/usr` links without rewriting them.
